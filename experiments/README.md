# Inventory feasibility versus RGB error

This reproducible synthetic comparison asks how enforcing stock limits changes
squared encoded-RGB error relative to unconstrained nearest-color matching.
It does not evaluate physical tiles, human preferences, or perceptual similarity.

Run from the installed checkout:

```sh
.venv/bin/python scripts/compare.py --check experiments/results.json
# To save a new result intentionally:
.venv/bin/python scripts/compare.py --output experiments/results.json
```

`results.json` records the actual results, input hashes, inventories, grid hashes,
seed, generator/Pillow versions, both methods' counts, excess tiles and error.
Each constrained bundle is checked by the independent instruction checker.

The landscape is generated by the documented example, without randomness.
The three noise cases use the same 256 RGB pixels from Python's `random.Random`
with seed **9771**, each channel sampled uniformly from integers 0–255. The seed
is reset before every noise case. Palette RGBs are fixed in `scripts/compare.py`;
only inventory changes. No external dataset, model, or paid compute is involved.
All inputs are already at grid resolution. Fit is `contain`, matte is white.

| Case | Cells | Constrained squared RGB error | Nearest squared RGB error | Nearest excess tiles | Constrained excess tiles |
| --- | ---: | ---: | ---: | ---: | ---: |
| Landscape, scarce teal | 384 | 3,055,128 | 76,768 | 73 | 0 |
| Noise, balanced | 256 | 2,565,479 | 2,551,984 | 8 | 0 |
| Noise, scarce red | 256 | 3,152,699 | 2,551,984 | 49 | 0 |
| Noise, unlimited | 256 | 2,551,984 | 2,551,984 | 0 | 0 |

The scarce-teal landscape has much worse RGB error when made feasible. That is
an expected cost of honoring inventory, not evidence of a visual improvement.
When stock cannot bind, the exact solver matches nearest-color error. Equal-cost
placements can differ without changing this objective.

These four small synthetic cases support reproducibility and demonstrate the
tradeoff, not broad performance or quality claims. The tests separately enumerate
all feasible assignments in **1,548** tiny binary-palette input/capacity cases
and **100** seeded three-color cases, comparing the solver's cost to the true
minimum. A hand-chosen case requires revising a greedy choice. Tests also cover
duplicate RGBs, zero-stock colors, and deterministic ties.
