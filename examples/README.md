# Synthetic landscape

`source.png` is an original, deterministic 24×16 synthetic landscape created by
`mosaic-parts example`. `inventory.json` contains illustrative approximations,
including only 70 dark-teal tiles. `preview.png` shows the constrained result.
These RGBs do not refer to verified commercial tile colors.

Regenerate the inputs and full plan in a new directory:

```sh
.venv/bin/mosaic-parts example --output example-output/input
.venv/bin/mosaic-parts convert example-output/input/source.png \
  --inventory example-output/input/inventory.json --width 24 --height 16 \
  --output example-output/plan
```

The source is generated by integer arithmetic without a random seed or external
assets. The preview is nearest-neighbor enlarged to show each tile clearly.

## Rectangular pieces

`pieces.json` supplies illustrative color-specific 1×1, 1×2 (rotatable), and 2×2
stock for the existing four-color sample palette. It is a separate inventory from
`inventory.json`, which constrains the initial image-to-color-grid assignment.
`packed-preview.png` is generated by the documented 6×4 conversion and packing
workflow in [the packing guide](../docs/packing.md): 24 cells, ten pieces, proven
optimal. The pieces and colors are sample data, not verified physical stock.

## Joint optimization sample

`joint-palette.json` contains the same four illustrative colors as the original
inventory, without 1×1 capacity fields. Pair it with `pieces.json` and the existing
`source.png` to run the [joint example](../docs/joint.md). `joint-preview.png`
shows the sampled source next to its six-piece plan; asterisks identify the five
cells differing from their nearest palette color. Error is 108,783 under budget
200,000. Historical previews and inputs are retained unchanged.
